Local graph inspection

ONNX viewer for understanding model exports

Check an ONNX export's interface before connecting it to an application. Explore declared inputs and outputs, node operations, initializers, and tensor relationships without sending the model to a server.

Open the ONNX inspection tool →

Check the interface your application will receive

Choose a .onnx file, then review input and output names, element types, and dimensions. Symbolic dimensions describe flexibility in the export; they do not supply a concrete batch size or sequence length. Compare the declarations with the inputs your application actually prepares.

Investigate an export change

Use the graph views to follow tensor producers and consumers and inspect node operations. Load a second ONNX file to compare extracted properties after reconversion or optimization. This helps locate interface or structural changes; it does not check numerical equivalence or execute operators.

External tensor data may live beside the ONNX file. The viewer can inspect declarations in the main protobuf, but it does not fetch or verify companion weight files. A small main file therefore does not imply a small resident model.

Choose the right memory planning path

The file report estimates initializer storage from shapes and data types, and recognizes certain explicit past/present cache interfaces. It cannot infer arbitrary intermediate activation peaks. For a decoder LLM with a known architecture, the manual memory estimator lets you explore context and concurrency without any file. It is not a general ONNX graph memory profiler.

Use the ONNX parser reference for supported fields, the graph guide to interpret connections, and the comparison guide for report scope. Have a GGUF download instead? Open the GGUF viewer.

The viewer is free and runs locally. Inspection does not prove that an inference runtime supports the export's operators. See the privacy policy for ordinary website requests.
