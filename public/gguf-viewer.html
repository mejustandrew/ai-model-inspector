Local model inspection

GGUF viewer for checking model variants

Have a GGUF file and want to check what is inside before loading it into an inference engine? Read its declared architecture, context settings, tokenizer metadata, and tensor shapes directly in your browser.

Open the GGUF inspection tool →

Check the file behind a model name

A download name alone cannot confirm a conversion's contents. Choose your .gguf file in the inspector, then check the architecture and context metadata against the model's published configuration. Missing fields stay missing; the viewer cannot establish training history or model quality from a filename.

Compare two local variants

Drop two GGUF files together to compare extracted information. Check changed metadata, tensor dimensions, and storage-type codes when investigating a conversion or selecting between variants. Export the parsed JSON for your own records or calculate a SHA-256 fingerprint to compare with a trusted published checksum.

Inspection reads descriptors rather than executing the model. It does not decode or validate all weight payloads, and matching metadata does not prove equivalent model behavior.

Plan the next step

The file-based report estimates inference memory from the tensor-data region and available cache metadata. If you have not downloaded a model, use the manual LLM memory estimator with its published architecture instead. For ONNX graph exports, use the ONNX viewer.

For field definitions and parser limits, see the GGUF format guide, metadata reference, and quantization projections. These references explain the report rather than requiring you to learn the format before opening a file.

Free and no account required. Model file processing stays on your device; ordinary website requests are described in the privacy policy.
